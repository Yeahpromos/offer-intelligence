# Offer 推广追踪 / Offer promotion tracking

入口：产品与 Offer → 推广追踪。页面为原生 Vue，沿用蓝色、键盘可操作日期控件、表格焦点及深浅主题。Level 0/1 可访问，Level 2 不可访问。两个运行环境共用 `offer_performance.py`，浏览器使用会话保护的只读 `GET /api/ui/db/offer-performance`。

## 追踪清单与时间

- 初始批次来自 `YP Amazon Offers (9-7) .xlsx`。两个工作表按 **Merchant ID 精确合并**，得到 63 个商家、294 条去重后的商家 ASIN 引用。原文件保持不变，SHA-256 和文件名保留在受保护的批次清单中；推荐备注是来源数据。
- 默认推送日期为 2026-09-07：推送前 08-31–09-06，观察期 09-07–09-13，各 7 天，包含端点。推送当天属于观察期。
- 可修改推送日期，也可指定 1–92 天的观察期；比较期紧接在观察期之前，长度相等。使用日历日期，不受浏览器时区或夏令时影响。
- 日期修改后需点击“应用时间”。报表、下钻和导出使用上一次应用的时间，避免未提交的输入污染现有结果。
- 可以导入 XLSX/XLS/CSV/TSV。只需 Merchant ID 和 Merchant Name（也支持商家 ID、商家名称/商家名），按 ID 合并所有工作表；品类和 ASIN 可省略，单清单最多 200 个商家。导入清单、手动新增的商家及修改后的默认日期保存在当前浏览器 `oi-promotion-batches-v1`。新批次不会自动同步给其他用户。
- 导入分为“选择文件 → 预览导入 → 弹窗核对 → 确认导入 → 下方选择清单”。文件选择不会触发读取或保存，日期在预览弹窗中确认，支持直接更改名称和日期。取消、读表失败或日期无效不会新增清单；文件保留以便重试。确认后保留当前追踪选择，并把焦点移到清单下拉框。
- 页面打开或应用时间时读取最新接口结果；关闭页面后不运行后台任务。

## 数据口径

| 展示 | 来源与规则 |
| --- | --- |
| Revenue | `cnpscy_amazon_order.amount` 或同义营收列，Amazon 归因销售额 |
| Orders | `total_purchases` 或同义购买数量列，不使用记录行数 |
| DPV / ATC | `detail_page_views` / `add_to_carts` 或同义列；不存在则为 `null` |
| Commission | `payout` 或 `commission` |
| Clicks | 优先整段使用 `cnpscy_amazon_click.click`；没有相应列时整段使用订单表点击列。跨日期、商家、媒体和历史月份保持同一来源，不叠加、不按营收分摊 |
| 历史月均、峰值 | 观察期之前六个自然月的实际归因营收，月度表包含所有六项指标；尚未覆盖到月末的月份不进入月均。不是全渠道销售量或产能预测 |
| 品类贡献 | 本批次商家清单品类与观察期营收相结合，可筛选、搜索及查看推荐 ASIN；不将它声称为媒体在所有商家中的偏好 |

接口动态读取实际表头，使用绑定的 Merchant ID 和日期参数、只读聚合查询。每次查询超过 25,000 个分组时明确报错，要求缩小日期范围，不静默截断。汇总只读商家每日和每月粒度。主视图自动读取一次清单关系数据，可按商家缩小接口查询范围；单独的历史下钻仍保留。

数据可用截止日取参与来源的最新记录日期与既有两天报表延迟的较早值。它表示数据记录新鲜度，**不保证每天已经完整回传**。未来日期显示待到数，整个周期尚未开始时指标为 `null`；未覆盖完整比较期时不显示涨跌百分比。来源为空或不可连接时保留商家清单并显示错误与 `—`，不会生成活动数据。基期为零不计算无限增长。

## 商家维护与可见关系

- “添加商家”只需 ID 和名称，可加入当前清单，也可单独建立追踪清单并指定推送日期。重复 ID 更新名称而不新增重复项；既有品类、ASIN 元数据保持可用。
- 修改后的预置清单成员与独立清单都会在刷新后恢复，最后选择的清单也会恢复。数据保存在当前浏览器，不修改数据库商家资料或原工作簿。
- 汇总指标下方固定展示“商家—媒体”和“商家单品—媒体”两个关系视图。每一行直接显示商家 → 单品/店铺 → 媒体，以及六项前后指标，不需要先打开商家下钻。
- 支持商家、媒体、ID、ASIN 搜索，前后活动周期筛选及指标排序。列表可以继续加载；点击商家可查看历史月度数据。
- 手机宽度下关系链纵向排列，商家、单品和媒体名称可以一起阅读；六项指标在表格内横向滚动。
- 品牌使用按主品类固定的颜色：导入预览、商家表、关系路径、详情标题及品类贡献图采用同一映射，子品类沿用主品类颜色，未分类使用中性色，并保留文字标签。
- 推广目标明细提供全部、单品、Storefront、未识别四个筛选项及数量。单品为蓝色、Storefront 为紫色、未识别为琥珀色；关系视图沿用相同标识。成交 ASIN 不会将未识别目标改标为单品。
- 推广 ASIN 进一步分为“清单内 ASIN”（蓝色）和“同品牌 · 清单外 ASIN”（青绿色），按该行 Merchant ID 对应的当前清单逐个精确匹配，不借用其他商家的清单。未提供 ASIN 清单时显示“清单未提供 ASIN”；Storefront 与仅有成交 ASIN 的记录不参与该划分。主关系视图与商家推广目标明细均提供范围筛选和数量。
- `action=relations` 一次查询清单中的多个商家。聚合键包含 Merchant ID，避免同一个媒体或同一个 ASIN 在不同商家之间串数。
- 关系查询按前/后两个周期聚合；查询截止日取所有参与来源和报表延迟的共同可用日期，避免待到数日期混入指标。返回 `aggregation=period`，不把周期总量伪装成每日数据，月度数据仍由汇总接口提供。
- 清单没有 ASIN 也可以展示记录中的单品—媒体关系；明确区分推广目标、成交 ASIN、Storefront 和未识别目标。

## 媒体与链接证据

- 按实际记录中的 `user_id` / `publisher_id` / `media_id` 分组，媒体名称表先按 ID 聚合，不通过重复维度行放大指标。
- 只有明确的 `promoted_asin` / `target_asin` / `link_asin` 或记录级目标 URL 才认定为推广 ASIN。
- Storefront 需要记录中的链接类型或 `/stores/`、`/shop/` 路径证据。
- 订单表中的普通 ASIN 作为 **成交 ASIN** 单独列出；它不能证明媒体推广了该 ASIN。链接证据缺失时显示未识别，不从商家主页推断。
- ASIN 层无法关联的点击和营收不会分摊给具体商品。明细中无证据对应的指标保持 `null`。
- 当前数据展示观察活动；前后差异不能单独证明推送造成了全部增量。

## 本地验证

`scripts/test_offer_performance.py` 覆盖周期边界、来源选择、空数据、SQL 参数约束、ASIN 证据、双运行环境路由和认证。Vue 测试覆盖日期应用、未到数展示、下钻、过期响应、焦点返回、筛选、导出及语言切换。

按用户要求，未调用实时接口或真实数据库做验证。浏览器排版检查使用明确的测试夹具，测试活动不会写入批次清单或生产数据。上线后的真实表头是否提供推广目标证据仍需实际环境决定。

本地浏览器已核对 1536px 桌面、390px 手机和深色主题，页面无横向溢出；日历 Escape 返回触发按钮，商家下钻移动焦点并支持返回。实际工作簿导入合并结果为 63 个商家和 294 条 ASIN 引用；重新读取导出的 XLSX，确认 63 个精确 ID、前后日期和指标字段。原工作簿 SHA-256 未变化。无数据库配置时本地接口报错，页面保留清单并显示 `—`。

新增关系视图与商家维护后，前端全量 464 项、后端专项 16 项测试通过。浏览器已验证仅含 Merchant ID 和 Merchant Name 的 CSV 导入（3 个商家、0 个导入 ASIN），报表测试夹具仍可展示 9 条单品/店铺与媒体关系；手动添加商家后刷新可恢复。

导入确认流程与颜色、ASIN 范围修订：前端全量 94 个文件、475 项测试通过；最新推广追踪与日历专项 42 项测试、类型检查和生产构建通过。浏览器核对了真实工作簿 63 个商家 / 294 ASIN 的预览、两列 CSV、无效日期修正、取消不保存、确认后选择、弹窗日历、清单内/同品牌清单外 ASIN 筛选、深浅主题和手机视图，指标使用测试夹具。未调用实时接口验证。
